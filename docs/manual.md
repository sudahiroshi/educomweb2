# 記事の書き方 手引き（委員会メンバー向け）

音響教育委員会の Web サイトに、お知らせや研究発表会などの記事を載せる手順です。
専用の「編集画面」で記事を書き、GitHub（記事を保管している場所）にボタン1つで登録します。登録すると数分でサイトに反映されます。

- サイト：<https://asj-edcom.acoustics.jp/>
- 編集画面：<https://asj-edcom.acoustics.jp/editor/>（メニューには出していないので、ブックマークしてください）

## 1. 最初に一度だけ行うこと

1. **GitHub のアカウントを作る**（持っていない場合）
   <https://github.com/signup> で、メールアドレスとパスワードを登録します。無料です。
2. **管理者にユーザー名を伝える**
   管理者がリポジトリ（記事の保管場所）にあなたを追加すると、GitHub から招待メールが届きます。メールの「View invitation」→「Accept invitation」を押してください。
3. **編集画面をブックマークする**
   <https://asj-edcom.acoustics.jp/editor/>

> 記事を登録するときは、ブラウザで GitHub にログインしている必要があります。

## 2. 全体の流れ

```
編集画面で書く ──→ 「記事をGitHubに追加」 ──→ GitHub で「Commit changes」 ──→ 数分でサイトに反映
（プレビューで見た目を確認）   （新しいタブが開く）
```

- 編集画面はブラウザの中だけで動きます。書いている途中の内容はどこにも送られません。
- 記事は GitHub で「Commit changes」を押した時点で登録され、自動でサイトが作り直されます。
- 書きかけの内容は、そのブラウザに自動で保存されます（別のパソコンやブラウザには引き継がれません）。

## 3. 編集画面で記事を書く

### 3.1 種類を選ぶ

画面上部の「種類」から選びます。

| 種類 | 載る場所 | 例 |
|---|---|---|
| お知らせ | 「お知らせ」 | サイトの更新、名簿の掲載、催しの案内 |
| 活動記録 | 「活動記録」 | ワークショップ、公開講座などの委員会活動 |
| 音響学会研究発表会 | 「研究発表会・国際会議」→「音響学会研究発表会」 | 春季・秋季研究発表会の音響教育セッション |
| 共催研究発表会 | 同 →「共催研究発表会」 | 他の研究会と共催の発表会 |
| 国際会議 | 同 →「国際会議」 | ICA、日米ジョイントミーティングなど |
| 運営委員 | 「運営委員」 | 年度ごとの名簿 |
| その他のページ | 必要に応じてメニュー | 委員会について、など |

研究発表会・活動記録・国際会議は、開催日を過ぎると自動で「開催予定」から「終了したもの」に移ります。手で直す必要はありません。

### 3.2 必ず入れる項目

- **スラッグ**：URL に使う英字の名前です。半角の英小文字・数字・ハイフン（-）だけで、3〜60文字にします。
  - 例：`asj-spring-2027`、`site-renewal`、`workshop-listening`
  - 日本語のタイトルから自動では作りません。内容が分かる短い英語にしてください。
  - 欄の下に、記事の **ID** と **保存先**（ファイル名）が表示されます。ID は日付とスラッグから自動で決まります（例：`2027-03-09-asj-spring-2027`）。
  - すでにある記事と同じ ID になると、エラーで知らせます。
- **タイトル**
- **日付**：お知らせは「掲載日」、研究発表会・活動記録・国際会議は「開始日」（1日だけなら終了日は空欄）、運営委員は「年度（西暦）」。

### 3.3 種類ごとの主な項目

**お知らせ**
- 概要：一覧に出す短い説明（空欄なら本文の最初の部分を使います）
- 関連記事：研究発表会などの記事を検索して選ぶと、お知らせの下に案内が出ます
- 本文

**研究発表会・活動記録・国際会議**
- 開始日・終了日、会場
- 外部リンク：「リンクを追加」で、表示名と URL の組を入れます（大会の公式サイト、プログラムの PDF など）
- セッション：「セッションを追加」で、セッション名・日付・時刻・会場（部屋）・座長・副座長を入れます
  - 講演は「講演を追加」で1行ずつ入れます（講演番号・演題・発表者・他・所属）
  - Excel などの表からまとめて入れるときは、「表計算ソフトから講演を貼り付ける」を開き、セルを選んでコピーし、貼り付けて「貼り付けた表を追加」を押します。列の順は **講演番号、演題、発表者、所属、他の有無** です
  - ↑↓ で並べ替え、× で削除します
- 活動記録に載せる（研究発表会の3種類だけ）：チェックを入れると、「活動記録」の一覧にも出ます
- 本文（任意）

**運営委員**
- 年度（西暦）と名簿の表（役職・氏名・所属）
- 「前年度の名簿を読み込む」を押すと、前の年度の名簿を写してから直せます
- Excel などからの貼り付けもできます（列の順：役職、氏名、所属）

**その他のページ**
- メニューに出す・メニュー表示名・メニュー順（小さいほど左）

### 3.4 本文の書き方

本文は「Markdown」という書き方で書きます。入力欄の上のボタンを押すと、記号が自動で入ります。

| やりたいこと | ボタン | 書き方の例 |
|---|---|---|
| 見出し | 見出し2・見出し3 | `## 見出し` |
| 太字 | 太字 | `**強調したい語**` |
| リンク | リンク | `[表示する文字](https://example.com/)` |
| 箇条書き | 箇条書き | 行の先頭に `- ` |
| 番号付きリスト | 番号付き | 行の先頭に `1. ` |
| 表 | 表 | `\| 見出し \| 見出し \|` の形 |
| 画像 | 画像 | [5章](#5-画像pdf-の付いた記事) を参照 |

- 段落を分けるときは、空行を1行入れます。
- 見出しは「見出し2」から使います（ページのタイトルが一番大きな見出しのため）。

### 3.5 プレビューとチェック

- 画面の右側（スマホでは「プレビュー」タブ）に、サイトと同じ見た目で表示されます。一覧やトップでの見え方も下に出ます。
- プレビューの中で、ライト／ダーク・文字サイズを切り替えて確かめられます。
- 入力に問題があると、欄の下と画面下の「チェック結果」に理由が出ます。直すまで出力のボタンは押せません。
  - よくあるもの：スラッグに大文字や日本語が入っている、終了日が開始日より前、URL が `https://` で始まっていない、セッションの日付が開催期間の外

## 4. GitHub に登録する（公開する）

1. 画面下の「出力」にある **「記事をGitHubに追加」** を押します。
2. 新しいタブで GitHub の画面が開き、ファイル名と内容が入った状態になっています。
   - ログインしていない場合はログイン画面になるので、ログインしてください。
3. 内容はそのままで、緑の **「Commit changes…」** を押します。
4. 確認の画面が出たら、「Commit directly to the `main` branch」が選ばれていることを確かめて、もう一度 **「Commit changes」** を押します。
   - 説明欄（Commit message）は、そのままでも、「2027年春季研究発表会の記事を追加」のように書いても構いません。
5. 数分でサイトに反映されます（[7章](#7-公開されたかの確認と失敗したとき)）。

**記事が長い場合**
長い記事は GitHub の画面に内容を直接渡せないため、ボタンを押すと記事の内容がコピーされ、ファイル名だけが入った画面が開きます。本文の欄をクリックして貼り付け（Ctrl+V／⌘V）てから、「Commit changes」を押してください。編集画面にもそのつど案内が出ます。

## 5. 画像・PDF の付いた記事

画像（JPEG・PNG・WebP・GIF）や PDF などを付けられます。画像は自動で長辺 1600px に縮小されます。

### 5.1 編集画面での準備

1. 先にスラッグと日付を入れて、記事の ID を決めます（画像の保存先と名前が ID から決まるため）。
2. 「画像・添付ファイル」の「ファイルを選ぶ」で、ファイルを選びます。名前は「記事の ID-番号」（例：`2026-08-01-summer-lab-01.jpg`）に自動で付け替えられます。
3. 本文の入れたい位置にカーソルを置き、画像の横の「本文に挿入」を押します。
4. 画像の説明（代わりのテキスト）を、目の不自由な方にも内容が伝わるように書き換えます。
   例：`![2026年夏休み 音の実験教室で、子どもたちが糸電話を試している様子](/files/events/2026-08-01-summer-lab/2026-08-01-summer-lab-01.jpg)`

### 5.2 登録の手順（この順で）

画像がある記事では、「出力」に番号付きの手順が出ます。

1. **「画像をダウンロード」**：名前を付け替えた画像が保存されます。
2. **「画像をアップロード」**：GitHub のアップロード画面が開きます。保存した画像をドラッグ＆ドロップし、「Commit changes」を押します。
3. **「記事をGitHubに追加」**：[4章](#4-github-に登録する公開する)と同じ手順で記事を登録します。

> 画像を先に登録してください。記事を先に登録すると、画像が届くまでのあいだ、画像が表示されません。

## 6. 載せた記事を直す・消す

### 6.1 直す

1. 編集画面の「既存の記事を読み込んで修正する」を開きます。
2. 「サイトにある記事から選ぶ」で記事を選び（タイトルや ID で絞り込めます）、「読み込む」を押します。
   - 手元に `.md` ファイルがある場合は、ファイルを選ぶかドラッグ＆ドロップでも読み込めます。
3. 内容を直します。直したことが分かるよう、**「更新日」** に今日の日付を入れてください。
4. 出力の **「既存の記事をGitHubで修正」** を押します。記事の内容がコピーされ、GitHub の編集画面が開きます。
5. GitHub の編集欄の中身をすべて選んで消し（Ctrl+A／⌘A → Delete）、貼り付けて（Ctrl+V／⌘V）、「Commit changes…」→「Commit changes」を押します。

> スラッグや日付（ID に関わる項目）を変えると、別の記事として新しく作られ、元の記事も残ります。その場合は、[6.2](#62-消す) の手順で元の記事を消してください。

### 6.2 消す

記事の削除は GitHub の画面で行います。

1. GitHub のリポジトリを開きます：<https://github.com/sudahiroshi/educomweb2>
2. `src/content/` の中の種類のフォルダ（`news`・`events`・`committee`・`pages`）を開き、消したい記事のファイルを開きます。
3. 右上の「…」から **「Delete file」** を選び、「Commit changes…」→「Commit changes」を押します。
4. 画像がある場合は、`public/files/` の中の同じ ID のフォルダの画像も、同じように消します。

## 7. 公開されたかの確認と、失敗したとき

### 7.1 反映までの時間

「Commit changes」を押すと、自動でサイトが作り直されます。通常 **2〜5分** で反映されます。サイトを再読み込みして確かめてください（変わらないときは、少し待ってからもう一度）。

### 7.2 成功・失敗の見方

GitHub のリポジトリのトップで、一番新しい変更の横に印が出ます。

| 印 | 意味 |
|---|---|
| 黄色の ● | 作り直しの途中 |
| 緑の ✓ | 成功。まもなく反映されます |
| 赤の × | 失敗。下の説明を見てください |

失敗すると、登録した本人に GitHub からメールが届きます。管理者にも「【ビルド失敗】」という題の知らせ（Issue）が届きます。

失敗には2種類あります。赤の × を押すと、どちらか分かります。

- **ビルド（npm run build）で失敗**：記事の内容に誤りがあり、サイトを作り直せなかった場合です。サイトは **前の状態のまま** で、壊れたページが公開されることはありません。
- **全ページの点検（npm run check:pages）で失敗**：サイトは作り直されて公開されていますが、見出しの使い方などに問題のあるページがあります。本文で `#`（一番大きな見出し）を使った場合などに起きます。

### 7.3 失敗したときにすること

1. 赤の × を押し、「Details」を開くと、エラーの内容が表示されます。ファイル名と項目名が出るので、どの記事のどの項目かを確かめます。
2. よくある原因：GitHub の画面で直接書き換えて、日付の形（`2027-03-09` の形）や記号が崩れた／貼り付けに失敗して内容が途中で切れた／本文で `#` の見出しを使った
3. 直し方：[6.1](#61-直す) の手順で記事を読み込み直して編集画面のチェックを通してから、もう一度登録します。分からないときは、そのまま管理者に連絡してください。

次に成功すると、管理者への知らせ（Issue）は自動で閉じます。

## 8. 困ったとき

| 困ったこと | 対処 |
|---|---|
| 書きかけのまま画面を閉じた | 同じパソコン・同じブラウザで編集画面を開くと「前回の入力内容があります」と出るので「復元する」を押します（画像は選び直してください） |
| 別の記事を書き始めたい | 「新規作成」を押します。書きかけの内容は消えます |
| 出力のボタンが押せない | 画面下の「チェック結果」の問題を直してください |
| GitHub の画面で「fork」（自分用の複製）を勧められる、または「404」になる | まだ書き込み権限がないか、別のアカウントでログインしています。fork はせず、招待を受け入れたか（[1章](#1-最初に一度だけ行うこと)）とログイン中のアカウントを確かめ、だめなら管理者に連絡してください |
| GitHub が使えない・分からない | 「zip で保存（予備）」で保存したファイルを管理者に送ってください |
| 開催予定の記事が「終了したもの」に移らない | 毎日 0 時過ぎに自動で作り直しています。見ている人のブラウザでも日付で判定しているので、通常は移ります。翌日になっても直らなければ管理者に連絡してください |

## 9. 管理者向けの作業

- **メンバーの追加・削除**（T-25 既定案：管理者が行う）
  GitHub のリポジトリの「Settings」→「Collaborators」→「Add people」で、メンバーの GitHub ユーザー名を入れて招待します（権限は Write）。退任したメンバーは同じ画面から外します。
- **ビルド失敗の知らせ**
  「【ビルド失敗】」「【定期ビルド失敗】」の Issue が管理者に割り当てられます。原因の記事を直すか、登録したメンバーに連絡してください。
- **定期ビルドの停止に注意**
  GitHub は、60日間リポジトリに変更がないと、定期ビルド（毎日 0:10）を自動で止めます。止まる前に GitHub から通知が来るので、リポジトリの「Actions」→「定期ビルド」→「Enable workflow」で再開してください。長く記事の更新がない時期は、ときどき「Run workflow」で手動で動かしても構いません。
- **デプロイフックの URL**
  定期ビルドは、GitHub の Secrets に登録した `CLOUDFLARE_DEPLOY_HOOK_URL` を使います。公開先を変えたときは、この値を新しいデプロイフックの URL に替えてください（値は秘密情報なので、人に見せたりファイルに書いたりしないでください）。
- **開発者向けの説明**は [README.md](../README.md) を見てください。
