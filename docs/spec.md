日本音響学会 音響教育委員会 Webサイト リニューアル

- 対象ドメイン：`asj-edcom.acoustics.jp`
- 作成日：2026-11-19
- 関連文書：`decision.md`（決定事項）、`plan.md`（実装計画）、`todo.md`（未決事項）

本書の「（D-xx）」は `decision.md` の番号、「（T-xx）」は `todo.md` の番号を指す。未決の項目は本書では仮の既定値を置き、`todo.md` で確定させる。

## 1. 概要

### 1.1 目的

旧サイト（HTML直接編集・フレーム構成）を廃止し、Astro による静的サイトに移行する。複数のメンバーが、専用の編集画面で記事を入力・プレビューし、GitHub 経由で直接公開できる体制を作る。

### 1.2 システム構成

```
メンバーのブラウザ
  └─ 編集画面（本番サイト内の非公開URL、静的ページ）
        │ 入力・プレビュー・チェック
        ├─ 「GitHubに追加」→ GitHub の新規ファイル作成画面（内容入り）→ コミット
        └─ ダウンロード（.md / 画像 / 予備のzip）
                          │
GitHub リポジトリ（main ブランチ）
        │ push を検知
Cloudflare（自動ビルド：astro build ＋ 検索索引作成）
        │ 成功時のみ公開。失敗時は直前の公開版が残る
asj-edcom.acoustics.jp
```

### 1.3 技術スタック（既定）

| 項目 | 採用 | 備考 |

## 2. コンテンツモデル

### 2.1 コレクション一覧

| コレクション | 内容 | 1ファイルの単位 | 置き場所 |
|---|---|---|---|
| `news` | お知らせ | 1件 | `src/content/news/` |
| `events` | 活動記録・音響学会研究発表会・共催研究発表会・国際会議 | 1回の開催／1活動 | `src/content/events/` |
| `committee` | 運営委員名簿 | 1年度 | `src/content/committee/` |
| `pages` | その他のページ（委員会紹介など） | 1ページ | `src/content/pages/` |

活動記録と研究発表会3種は項目が共通のため（D-13）、`events` 1つのコレクションにまとめ、`kind` で種類を分ける。

すべてのファイルは **フロントマター付きMarkdown（.md）**、文字コードは UTF-8 とする。

### 2.2 ファイル名とID

| コレクション | ファイル名 | 例 |
|---|---|---|
| `news` | `{掲載日}-{スラッグ}.md` | `2026-11-19-site-renewal.md` |
| `events` | `{開始日}-{スラッグ}.md` | `2027-03-09-asj-spring-2027.md` |
| `committee` | `{年度}.md` | `2026.md` |
| `pages` | `{スラッグ}.md` | `about.md` |

- 日付は `YYYY-MM-DD`。
- スラッグは半角英小文字・数字・ハイフンのみ（正規表現 `^[a-z0-9]+(-[a-z0-9]+)*$`）、3〜60文字。
- ファイル名（拡張子を除く）を記事のIDとし、URLにもそのまま使う。
- 同じIDが既に存在する場合、編集画面で警告する（既存記事一覧と照合。3.8）。

### 2.3 共通の型

```ts
// 日付：YYYY-MM-DD 形式の文字列（タイムゾーンを持たない日付として扱う）
date: z.string().regex(/^\d{4}-\d{2}-\d{2}$/)  // ＋実在日付チェック

// 時刻：HH:MM（24時間制）
time: z.string().regex(/^([01]\d|2[0-3]):[0-5]\d$/)

// 外部リンク
link: z.object({
  label: z.string().min(1),           // 表示名（例：大会公式サイト）
  url:   z.string().url(),            // https:// で始まるURL
})
```

日付は文字列のまま保持し、時差による日付ずれを避ける。比較・表示はすべて日本時間（Asia/Tokyo）で行う。

### 2.8 画像・添付ファイル

- 置き場所：`public/files/{コレクション}/{ID}/`
  - 例：`public/files/news/2026-11-19-site-renewal/photo-01.jpg`
- 本文からの参照は絶対パス：`/files/news/2026-11-19-site-renewal/photo-01.jpg`
- 画像の命名：`{ID}-{連番2桁}.{拡張子}`（編集画面が自動で付け替える。D-44）
- 旧サイトから移行した添付ファイル：`public/files/legacy/`（旧サイトのフォルダ構成を保つ）
- `public/` に置くのは、画像の追加が記事より後になっても**ビルドが失敗しない**ようにするため（Astro の画像最適化は使わない）。画像の推奨サイズは T-19。

## 3. 表示ロジック

### 3.1 年度

- 年度は4月始まり：`fiscalYear(d) = (月 >= 4) ? 年 : 年 - 1`（D-26）
- `events` の年度は **開始日** で決める。

### 3.2 開催状態

- 終了基準日 `end = endDate ?? startDate`
- 日本時間の今日 `today` に対して、`today <= end` なら **開催予定**、`today > end` なら **終了**（終了日の翌日0時に切り替わる。D-25）
- 開催中（開始日〜終了日）も「開催予定」欄に含める。表示上「開催中」ラベルを付けるかは T-29。

### 3.3 ビルド時と閲覧時の振り分け（D-24）

1. **ビルド時**：ビルド日（日本時間）を基準に、各記事を「開催予定」「終了（年度別）」に振り分けてHTMLを生成する。
2. **閲覧時**：開催予定の各項目に `data-end="YYYY-MM-DD"` と `data-fy="2026"` を付けておき、ページ読み込み時にスクリプトが日本時間の今日と比較する。
   - 終了していた項目は「開催予定」から外し、同じページ内に `data-fy` が一致する「終了」リストがあれば、その **先頭** に移す（終了リストは新しい順のため）。
   - 一致するリストがページ内にない場合（年度の変わり目など）は非表示にし、該当年度ページへの導線は年度リンク一覧で確保する。
   - 開催予定が0件になったら「現在予定されている開催はありません」と表示する。
3. スクリプトが無効でもビルド時点の振り分けで表示できること。
4. 日本時間の今日は `Intl.DateTimeFormat('sv-SE', { timeZone: 'Asia/Tokyo' })` 等で `YYYY-MM-DD` を得て、文字列比較する。

### 3.4 並び順

| 一覧 | 並び |
|---|---|
| 開催予定 | 開始日の **昇順**（近いものが上）（D-23） |
| 終了（年度別） | 開始日の **降順**（新しいものが上）（D-22） |
| お知らせ | 掲載日の降順（同日は更新日→ID） |
| 運営委員の年度リンク | 年度の降順 |

同じ開始日の場合は終了日、次にIDで並べて順序を安定させる。

### 3.5 活動記録に載る記事

`kind == 'activity'` または `listInActivities == true` の `events`。

### 3.6 日付の表示形式

| 用途 | 形式 | 例 |
|---|---|---|
| 掲載日・更新日 | `YYYY年M月D日` | 2026年11月19日 |
| 開催日（1日） | `YYYY年M月D日（曜）` | 2027年3月9日（火） |
| 開催日（同月内の複数日） | `YYYY年M月D日（曜）〜D日（曜）` | 2027年3月9日（火）〜11日（木） |
| 開催日（月またぎ） | `YYYY年M月D日（曜）〜M月D日（曜）` | |
| 開催日（年またぎ） | 両側を年から表記 | |
| セッション日時 | `M月D日（曜） HH:MM〜HH:MM` | 3月10日（水） 13:00〜15:00 |
| 一覧カードの日付ブロック | 年／月／日（範囲） | 案Bの日付ブロック |

`<time datetime="…">` を必ず付ける。

### 3.7 講演の発表者表示

`hasCoauthors` が `true` のとき「`{presenter}` 他」、`false` のとき「`{presenter}`」。所属は別の列に表示する。

### 3.8 既存記事一覧（編集画面用）

ビルド時に、全コレクションのID・タイトル・種類・日付を `/editor/index.json` として出力する。編集画面はこれを使い、ID重複の警告と、お知らせの「関連記事」の選択肢を作る。

### 4.2 年度別ページの規則（D-27）

- 一覧ページ（年度なし）は「開催予定」と **当年度**（ビルド日の年度）の終了分を表示する。当年度の終了分が0件なら、終了分がある最新年度を表示する。
- 一覧ページと各年度ページの下部に、終了分がある全年度へのリンクを降順で並べる（例：2025年度｜2024年度｜…）。現在表示中の年度は `aria-current="page"`。
- 年度ページは終了分のみを表示する（開催予定欄なし）。

### 4.3 ナビゲーション（D-29〜D-31）

メインメニューの順序：

1. お知らせ
2. 活動記録
3. 研究発表会・国際会議 ▾（サブメニュー：音響学会研究発表会／共催研究発表会／国際会議）
4. 運営委員
5. その他のページ（`pages` のうち `showInMenu: true` を `menuOrder` 順）

- サブメニューはボタンで開閉し、`aria-expanded` を切り替える。Esc で閉じ、フォーカスをボタンに戻す。メニュー外クリックで閉じる。
- 幅 768px 未満では、メニュー全体を「メニュー」ボタンで開閉する折りたたみ表示にする。サブメニューは入れ子のリストとして展開する。
- 現在のページに対応する項目に `aria-current="page"` を付け、見た目でも区別する。

### 4.4 共通の構成要素

- スキップリンク（「本文へ移動」）
- ヘッダー：ロゴ（波形マーク＋「日本音響学会／音響教育委員会」）、文字サイズ切替、テーマ切替、メインメニュー

| トップの見出し（h1） | 2.1rem（スマホ 1.6rem） | 700 |
| 節見出し（h2） | 1.4rem | 700 |
| カード見出し（h3） | 1.1rem | 700 |
| 本文 | 1rem | 400 |
| 補足・日付 | 0.85rem | 400 |
| 種類ラベル | 0.8rem | 700 |

### 5.3 レイアウト

- 最大幅 1160px、左右の余白 24px（幅 600px 未満は 16px）
- カード：角丸 18px、枠線 1px、背景 `--color-surface`
- 日付ブロック・小部品：角丸 12px
- メニュー・切替ボタン：ピル型（角丸 999px）
- 2列のカード並び：`grid-template-columns: repeat(auto-fit, minmax(min(100%, 420px), 1fr))`
- 波形のあしらい：トップの紹介文の下に横幅いっぱいの波線（主線＝アクセント、副線＝`--color-wave-sub`）。装飾なので `aria-hidden="true"`。ロゴの波形マークも同様。
- 影は使わない（サブメニューのドロップダウンのみ薄い影）。グラデーションは使わない。

### 5.4 ライト／ダークモード（D-48）

- `<html data-theme="light|dark">` で切り替える。
- 初期値：`localStorage` に保存値があればそれ、なければ `prefers-color-scheme` に従う。
- `<head>` 内の小さなインラインスクリプトで、描画前に `data-theme` を設定する（ちらつき防止）。
- 切替ボタンはアイコンのみ（ライト時は月、ダーク時は太陽）。`aria-label` に「ダークモードに切り替え／ライトモードに切り替え」。
- 保存キー：`asj-edcom:theme`（値 `light` / `dark`）
- `localStorage` の読み書きは `try/catch` で囲み、使えない環境でも動作すること。
- OSの設定が後から変わった場合、保存値がなければ追従する。

### 5.5 文字サイズ（D-49）

- `<html data-font-size="normal|large|xlarge">` → `html { font-size: 100% / 125% / 150% }`
- ボタン表記：ノーマル／大／特大。`role="group" aria-label="文字サイズ"`、各ボタンに `aria-pressed`。
- 保存キー：`asj-edcom:font-size`
- テーマと同じインラインスクリプトで描画前に適用する。
- 特大（150%）・幅 320px でも横スクロールが出ないこと（表はスクロール枠内に収める）。

| 名前 | 用途 |
|---|---|

## 6. 編集画面（`/editor/`）

### 6.1 前提

- 静的ページ。サーバーへの送信は行わない（D-03）。
- メニューに出さない。`<meta name="robots" content="noindex">`、サイトマップ・検索索引から除外（D-42）。
- 入力途中の内容は `localStorage` に自動保存し、再訪時に復元を提案する（端末ごと）。

### 6.2 画面構成

```
┌ 種類の選択：お知らせ／活動記録／音響学会研究発表会／共催研究発表会／国際会議／運営委員／その他のページ
├ 操作：新規作成｜.mdを読み込む｜下書きを消去
├──────────────────────┬──────────────────────┤
│ 入力フォーム（種類ごと）   │ プレビュー（本番と同じ見た目）│
│                            │ ライト/ダーク・文字サイズ切替 │
├──────────────────────┴──────────────────────┤
└ チェック結果 ／ 出力：GitHubに追加｜画像をアップロード｜ダウンロード｜コピー｜zip（予備）
```

幅の狭い画面では「入力」「プレビュー」をタブで切り替える。

### 6.3 入力フォーム

種類に応じて 2章の項目を入力欄として出す。

- **共通**：スラッグ入力欄（タイトルから自動生成はしない。日本語のため）。ファイル名・保存先パスを常に表示する。
- **本文（Markdown）**：テキストエリア＋書式ボタン（見出し2・見出し3、太字、リンク、箇条書き、番号付きリスト、表、画像挿入）。ボタンは選択範囲にMarkdown記法を挿入する（D-46）。
- **外部リンク**：行の追加・削除・並べ替え（表示名＋URL）。
- **セッション**：セッション単位で追加・削除・並べ替え。各セッション内に講演の表（講演番号・演題・発表者・他・所属）を持ち、行の追加・削除・並べ替えができる。
  - 表計算ソフトからコピーした表（タブ区切り）を貼り付けて講演を一括追加できる（列順：講演番号、演題、発表者、所属、他の有無）。
- **活動記録に載せる**：研究発表会3種のみ表示するチェックボックス。
- **関連記事**（お知らせ）：既存の `events` から検索して選ぶ（3.8 の一覧を使用）。
- **運営委員**：年度＋名簿の表（役職・氏名・所属）。タブ区切りの貼り付けに対応。前年度の名簿を読み込んで編集を始められる。
- **その他のページ**：タイトル、メニュー表示名、メニューに出す、メニュー順、本文。
- **日付入力**：`<input type="date">`。時刻は `<input type="time">`。

### 6.4 プレビュー

- 入力に合わせて即時更新する（入力停止後 300ms 程度で反映）。
- 記事詳細ページと同じコンポーネント・CSSで描画する。トップや一覧での見え方（カード表示）も併せて表示する。
- Markdown は Astro と同じ GFM 準拠で変換する。生のHTMLはプレビューでも本番でも無害化して扱う（本文中の `<script>` 等は不可）。
- 画像は選択したローカルファイルを、付け替え後のパスで表示する。

### 6.5 チェック（D-41）

- サイトと **同じZodスキーマ** で検証する（`src/schemas/` に定義し、コンテンツ設定と編集画面の両方から読み込む）。
- 必須項目の抜け、日付形式、開始日≦終了日、セッション日付が開催期間内、開始時刻＜終了時刻、URL形式、スラッグ形式、ID重複（既存記事一覧と照合）をチェックする。
- エラーは該当する入力欄の横と、画面下部の一覧に表示する。エラーがあるあいだ出力ボタンは押せない。

### 6.6 出力（D-43〜D-45）

| ボタン | 動作 |
|---|---|
| **記事をGitHubに追加** | `https://github.com/{owner}/{repo}/new/{branch}?filename={パス}&value={内容}` を新しいタブで開く。メンバーは画面下の「Commit changes」を押すだけ |
| **画像をアップロード** | `https://github.com/{owner}/{repo}/upload/{branch}/public/files/{コレクション}/{ID}` を開く |
| **ダウンロード** | `.md` と、名前を付け替えた画像を保存する |
| **コピー** | `.md` の内容をクリップボードにコピーする |
| **zipで保存（予備）** | リポジトリと同じフォルダ構成で `.md` と画像をまとめた zip |

- `{owner}`・`{repo}`・`{branch}` は設定ファイル（`src/config/site.ts`）で定義する。
- 内容が長くURLの上限を超える場合（しきい値は実測で決める。plan 8章）は、内容をクリップボードにコピーしたうえで、ファイル名だけを指定した新規作成画面を開き、貼り付けるよう案内する。
- 画像付き記事の手順（D-44）を、出力欄に番号付きで表示する。
- 既存記事を読み込んで修正した場合は、新規作成ではなく **既存ファイルの編集画面**（`/edit/{branch}/{パス}`）を開き、全文を差し替えてもらう案内を出す（新規作成画面は同名ファイルを作れないため）。

### 6.7 既存記事の読み込み（D-47）

- 手元の `.md` を選ぶ（またはドラッグ＆ドロップ）と、フロントマターと本文を解析してフォームに反映する。
- パスやファイル名から種類とIDを判定する。判定できない場合は種類を選ばせる。
- 既存記事一覧（3.8）から選んで、GitHub の raw URL（`https://raw.githubusercontent.com/{owner}/{repo}/{branch}/{パス}`）から直接読み込む機能も付ける（リポジトリは公開。D-54）。

### 6.8 出力ファイルの書式

- フロントマターのキー順は 2章の表の順。
- 空の任意項目は出力しない。
- 文字列は必要なときだけ引用符で囲む（`yaml` パッケージの既定）。
- 改行コード LF、末尾に改行を1つ。

## 7. 検索・RSS・メタ情報

- **検索（D-52）**：Pagefind。対象はお知らせ・記事詳細・運営委員・その他のページ。一覧ページ・編集画面・404 は除外（`data-pagefind-ignore` 等）。検索ページは `/search/`、ヘッダーかフッターから入れる。
- **RSS（D-52）**：`/rss.xml`。項目はタイトル・リンク・掲載日・概要。対象範囲は T-17。
- **メタ情報**：`<meta name="description">`、OGP（`og:title` / `og:description` / `og:url` / `og:type`）。OGP画像は T-21。
- **言語**：`<html lang="ja">`。英語のタイトル等は必要に応じて `lang="en"` を付ける（T-26）。

## 8. アクセシビリティ（D-53）

JIS X 8341-3:2016 の適合レベル AA 相当を目標とする。主な要件：

- コントラスト比：通常文字 4.5:1 以上、大きな文字・UI部品 3:1 以上（ライト・ダーク両方）
- キーボードだけで全操作が可能。フォーカス枠を常に見えるようにする（`--color-focus`、3px）
- ボタン・リンク・入力欄は正しい要素を使う（`div` にクリック処理を付けない）
- アイコンだけのボタンには `aria-label`
- 押せる部品の大きさは 44×44px 以上
- 見出しレベルを飛ばさない。ページごとに `h1` は1つ
- 表には `<th scope>` と `<caption>`（セッション名を見出しに）
- 文字サイズ 200% 相当（ブラウザ拡大）・特大設定で内容が欠けない
- `prefers-reduced-motion` を尊重する（動きのある表現は控えめに）
- 外部リンクは見た目と読み上げで外部と分かるようにする

## 9. 公開と運用

### 9.1 リポジトリ

- GitHub。オーナーは管理者の個人アカウント、**公開リポジトリ**（D-54）。
- 既定ブランチ `main`。メンバーは書き込み権限を持ち、`main` に直接コミットできる（D-40）。

### 9.2 ビルドと公開

- Cloudflare の GitHub 連携で、`main` への push ごとに自動ビルド・公開。
- ビルドコマンド：`npm run build`（`astro build` のあと `pagefind --site dist`）
- 出力：`dist/`
- Node.js のバージョンは `.nvmrc` 等で固定する。
- ビルド失敗時は公開されず、直前の版が残る（D-41）。失敗の通知先は T-11。
- 開催予定の切り替えのため、**毎日1回の定期ビルド** を設定する（Cloudflare のデプロイフックを GitHub Actions の定期実行から呼ぶ）。閲覧時の判定（3.3）と併用し、年度別ページの更新漏れを防ぐ。

### 9.3 ドメイン（D-38）

`asj-edcom.acoustics.jp` を Cloudflare のカスタムドメインとして設定し、学会事務局に acoustics.jp のDNSへ CNAME の追加を依頼する。旧サイトからの切り替え日は T-24。

### 9.4 運用手引き

メンバー向けに、編集画面の使い方・GitHub でのコミット手順・画像付き記事の手順・ビルド失敗時の確認方法をまとめた手引き（`docs/manual.md`、サイトとは別）を用意する。

## 10. 移行（D-32〜D-35）

1. 旧サイトのHTML・添付ファイル一式を `legacy/`（ビルド対象外）に置く。
2. ISO-2022-JP（その他混在する文字コード）を UTF-8 に変換する。
3. フレーム構成を解析し、全ページの一覧（URL・タイトル・種類の推定）を作る（`docs/migration/inventory.md`）。
4. ページごとに、2章のどのコレクションに当たるか、またはその他のページかを人が確定する（T-01）。
5. 変換スクリプトでHTMLから本文と日付等を取り出し、フロントマター付き `.md` を生成する。セッション・講演一覧は表の構造から抽出を試み、できないものは本文に残して要確認リストに載せる。
6. 添付ファイルを `public/files/legacy/` に移し、本文中のリンクを書き換える。
7. 外部リンクの死活を確認し、切れているものを一覧にする（扱いは T-31）。
8. 要確認リストを人が見て修正する。
9. 旧URL のリダイレクトは行わない（D-33）。
